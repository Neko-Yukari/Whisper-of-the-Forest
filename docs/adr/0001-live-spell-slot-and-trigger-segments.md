# ADR 0001：当前槽即时切换、去草稿与分段触发

- 状态：已被取代（2026-11-05）
- 日期：2026-10-30

> **取代说明（2026-11-05）**：决策 1、2、5 仍然有效。决策 3、4 已全部移除：命中触发符文废弃，`SpellSegment`、`spellSegmentIndex`、触发服务都已删除，法术计划只有一段。
> 时机类效果改由滞留、地印、延迟把右侧效果编成嵌套载荷来表达。原符文见 `_Deprecated/1.7/Defs/Experiments/Spellbook.Trigger.xml`。

## 背景

原魔术书把“正在编辑的槽”和“人物当前施法槽”分开保存：点击书签只改编辑槽，只有点保存才调用 `SetActiveSlot`。因此人物下方施法按钮长期停在上次保存的槽，用户看到的是“无论点哪个书签都只显示第三个”。

同时，原编辑流程依赖草稿、覆盖确认和关窗确认，和新生魔艺“点符文即组装、点创建即保存”的体验不一致。用户还要求支持命中触发：一段法术命中后，从命中处继续施放下一段。

## 决策

1. **当前槽就是编辑槽。** 点击任意书签立即调用 `GameComponent_Spellbook.SetActiveSlot`；空槽也切换，人物施法按钮显示“空槽”并禁用。
2. **去掉草稿与确认弹窗。** 点左侧符文直接追加到法术栏，点法术栏符文直接移除；“创建”写入当前槽；切槽或关书丢弃未创建改动；“清空”只清空法术栏；“删除此槽”直接清空保存槽。
3. **触发采用段列表 + 前向指针。** 法术编译为有序 `SpellSegment` 列表；每段带 `triggerOnHit`。射弹携带完整计划快照和 `spellSegmentIndex`，命中后执行当前段，并让指针指向下一段。
4. **下一段生成方式。** Self/Touch 作用于被命中的 Thing（没有则命中格）；Projectile 按接触面法线在目标后方生成，不回头追踪。出界、过期、目标失效不触发。
5. **增幅兼容由 XML 声明。** 每个符文用 `compatibleAugments` 列出可接增幅，代码只读列表；不维护第二份 C# 规则。

## 后果

- 书签点击和人物按钮同步，不再需要“保存后才生效”的心智模型。
- 旧存档没有 `segments` 时，从旧 `form/steps` 合成单段计划；旧射弹继续按原路径结算。
- 触发只向前消费一次，不存在递归回环；分裂只造成有限扇出。
- UI 和编译器共享 `CanAppend`，半透明/红字提示与实际保存校验不会分叉。
- 失去“草稿还原”和覆盖确认；这是有意为之，换取了更接近新生魔艺的即时编辑体验。

## 备选方案

- **保留草稿，只在保存时切换当前槽**：改动小，但用户明确反馈的按钮不同步问题仍在。
- **Ars 的“剩余全部法术”触发模型**：实现简单，但用户要的是“下一段”，且多段链的指针语义更接近 Noita。
- **Noita 的抽牌模型**：需要引入牌组/手牌/弃牌和抽取计数，超出本轮框架实验范围。
