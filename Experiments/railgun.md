# 轨道炮符文实验

状态：实现中（子代理模型路由中断，等待从半成品恢复）

当前恢复点：复合符文编译、全贯穿瞄准、蓄能后结算和独立 Vfx 请求/定义/服务已写入；轨道炮 worker、Def、Shader、图标与本地化尚未完成。`check-spells` 独立构建目前因检查工程未包含 `Vfx/**/*.cs` 报 CS0234，最终 DLL 未改。恢复实现时复用原子会话，不从空白重做。

## 1. 目标

在现有法术书中增加一个“形式与效果合一”的复合符文入口，并用“轨道炮”验证这条入口。另设独立视效系统承接法术发出的语义请求，视觉时长、颜色、粒子与屏幕效果不进入法术公共参数。

本轮先验证完整效果、法术与视效对接，以及可复用脚手架，不做法力消耗与平衡定型。

## 2. 用户已确认的范围

- 新符文名为“轨道炮”，一个符文同时包含形式与效果。
- 主束视觉宽度和命中走廊宽度均为 2.5 格。
- 命中全贯穿，不被 Pawn、建筑、墙体或山体截停。
- 伤害只是占位值，首版不消耗精神力或心灵熵。
- 视觉顺序：发射点逐渐蓄能；发射瞬间全屏短暂压暗；主束保持高亮；环绕电弧；余辉消散。
- 主束默认白金色核心、橙金色外层辉光，参考用户提供的 Project Wingman 轨道炮截图，不复制其素材。
- 可以使用 RimUnity 现有能力，也可以自制实现。优先完成可复用脚手架，不为单项视觉效果扩建无关系统。

## 3. 非目标

- 不实现基因资源条、产灵能建筑、法力药水或法杖平衡。
- 不新增其他高级符文。
- 不做轨道炮与分裂、加速、范围等增幅的组合。
- 不承诺本轮支持“命中触发 → 轨道炮”；若复合入口天然支持，则单独记录，未实测不得宣称可用。
- 不修改旧三种形式、旧效果和旧预设的行为，不把旧飞弹视觉迁移到新视效系统。
- 不提交、不推送、不发布。

## 4. 实现契约

### 4.1 法术入口

- 新 Def 名：`WotF_Form_Railgun`。
- 书页中只放这一个符文即构成完整法术，不再需要追加普通 Effect。
- 该符文不接受现有增幅；UI 的合法性判断、保存校验和实际施法必须共用同一套编译规则。
- 法术可以保存到法术槽，通过原人物 Gizmo 和共享 `SpellService` 施放。
- 目标可以是 Pawn、建筑或地面。全贯穿法术的瞄准不被墙体和山体的视线检查挡住。
- 首版只要求 `[WotF_Form_Railgun]` 单符文配方；不要为支持其他组合改动旧语法。

### 4.2 法术参数

以下为占位值，必须能从法术 Def 调整：

| 参数 | 初始值 |
| --- | ---: |
| 伤害 | 120 |
| 穿甲 | 0.5 |
| 命中宽度 | 2.5 格 |
| 射程 | 0（表示全图，只受地图边界截断） |
| 蓄能 | 90 tick |

蓄能会影响伤害何时结算，因此属于法术参数。视效系统读取这个进度，但不在法术参数中定义光球、主束、余辉或压暗时长。

伤害沿用现有法术伤害类型和穿甲约定。数值不构成平衡结论。

### 4.3 命中

- 瞄准点可以是地图内任意格，不套用普通法术的 24.9 格射程，也不套用旧的 40 格限制。
- 从施法者当前位置沿瞄准方向发射，只在地图边界结束；Def 的 `range` 大于 0 时才额外限制长度。
- 蓄能期间目标点锁定；施法者移动时，发射起点使用发射瞬间的位置。
- 对走廊内每个可受伤的 Pawn 和可受伤 Thing 至多结算一次。
- 施法者自己不受伤；其他目标不做友军豁免。
- 墙体、门、建筑、植物和山体不阻断射线。它们受损或被摧毁都不会影响后续目标。
- 命中结算与视觉生命周期分离；视觉失败不能回滚或重复伤害。

### 4.4 独立视效系统与对接

- 新建通用视效目录和入口，例如 `Vfx/`。法术只能通过视效请求对接，不直接创建 RimUnity GameObject、材质、粒子或 `EfxClip`。
- 新视效 Def 名：`WotF_Vfx_Railgun`。它选择自己的 worker，并持有主束高亮、余辉、压暗、颜色和电弧等本效果专属参数。
- 法术请求只提供语义上下文：地图、跟随对象、起点、目标点、方向、长度、宽度、蓄能 tick，以及视效 Def 名。请求不包含“压暗时长”等并非所有法术都有的字段。
- 视效系统负责 worker 创建、逐帧更新、停止、到期和地图退出清理。视觉失败不能回滚或重复法术伤害。
- 蓄能光效跟随请求中的对象；轨道炮 worker 自行决定蓄能光球、主束、环绕电弧和全屏压暗。
- 发射时使用 RimUnity `ScreenEfx` 或等价入口压暗地图；主束在压暗之后叠加，不能一起变黑。
- 主束和电弧使用程序化材质、ShaderDef + GLSL 或现有粒子能力，不要求 Unity 工程。
- 暂停、读档、切换地图和退出存档时不得遗留全屏压暗、材质或 GameObject。
- 视觉表现按真实时间消退；伤害按游戏 tick 结算。
- 施法、蓄能和视效不得移动、缩放或重置地图相机。相机保持玩家在施法前的观察位置；全屏压暗只改变像素，不改变相机状态。

## 5. 已核实的接口事实

- `SpellCompiler` 目前要求 Form 开头、末段至少一个 Effect；复合入口需要在这里计数，不在书页里另写特例。
- `SpellService.IsTargetable` 当前对非 Touch 形式统一要求 `GenSight.LineOfSight`，轨道炮必须走独立规则。
- `SpellService.TryCast` 当前只有 Projectile 与直接效果两条路径；复合形式需要进入自己的施法服务。
- RimUnity `Shader.Find` 调用 `ShaderRegistry.TryResolve`，并非只能读取 Unity 导出的 catalog。见本机反编译 `RimUnity.Shader.Find`。
- `EfxFrameBuilder.AddPass` 接受游戏材质；`ScreenEfx` 在地图与 Bloom 合成后、游戏 UI 前执行。见 RimUnity `Docs/zh-CN/ScreenEfx.md`。
- `RimUnity.Camera.WorldToScreenPoint` 提供世界到屏幕坐标转换。实际地图相机是否由该入口暴露，需要在实现时核实；未核实前不得假定。

## 6. 验收

### 6.1 静态检查

- 全项目编译 0 error；保留项目已有检查。
- `build.ps1 -Verify`、`check-defs`、`check-spells`、`check-spellbook-ui` 通过，或因本轮新增 Def 合理扩展后通过。
- 增加复合符文语法、单符文完整性、非法追加和几何命中的行为检查。
- 检查必须证明旧配方仍按原规则通过或被拒绝。

### 6.2 真实游戏

在隔离 `-savedatafolder` 与 `-wotflab` 实例中验证：

1. `WotF_Form_Railgun` 成功加载，书页能保存单符文配方，人物 Gizmo 显示该配方。
2. 施法后先经过蓄能再结算；不是点击瞬间无延迟伤害。
3. 走廊内两个以上目标各受伤一次，走廊外目标不受影响。
4. 墙后和山后的目标仍被命中；障碍不会截停后续结算。
5. 同一多格建筑不会被重复结算，施法者不受伤。
6. 不扣精神力或心灵熵；本轮没有新增资源消耗。
7. 保存并读回含轨道炮的法术槽，仍能再次施放。
8. 切图或退出后没有残留全屏压暗与持续错误；日志无新增 ERROR/Exception。

截图只用于排查渲染故障和保留当前画面，不把截图当作命中或资源结论。最终光束、电弧、压暗和蓄能观感由用户判断。
